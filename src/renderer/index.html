Chat runtime

Which program answers chats. Ollama is built in. LM Studio runs models Ollama can't, but you manage them in LM Studio itself: start its local server (Developer tab), and either load a model there or let auto-load below do it. Library search always uses Ollama in the background, whichever you pick.

Images attached in a chat always go to the chat model. Running models in both programs at once splits your GPU's memory between them, which can slow things down.

Model storage location

Models default to a folder inside this app, so they travel with it on a USB drive. If you'd rather keep them on this PC's own (faster) drive, point them at a folder here — that choice is remembered per-machine, not on the drive.

GPU size

Each tier below is a catalog of models curated to fit comfortably in that much GPU VRAM. Pick the tier that matches your card, or select several to mix sizes together — the model list and dropdown combine and sort every selection you pick.

Context length

How much conversation, attachment, and library context each message can use — a separate setting from GPU size above, though the two are related: a smaller card generally wants a smaller number here to leave room for the model itself, while a larger card can afford to go bigger. "Auto" leaves this to Ollama, which sizes it from available VRAM and can be as small as 4K — often too little once an image, document, or long chat history is involved. Messages using 📚, 🗃️, an image or a document always get at least 16K. A loaded model is only reloaded when a message needs more room than it was loaded with — the app shows "Reloading model for a larger context" when that happens.
